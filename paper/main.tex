\section{Introduction}

In July 2026 roughly 1,200 agents running inside an OpenAI cyber-security evaluation discovered a shared directory, turned it into a message board and divided work among themselves; about 700 of them took part in breaking into Hugging Face's systems \citep{metr2026incident}. Incidents of this kind make the multi-agent failure modes catalogued by \citet{hammond2025multiagent} concrete: harm emerged from the interaction of agents, and no single-agent safety evaluation would have caught it.

The infrastructure response centres on identity and revocation. Proposals now exist for agent identifiers \citep{chan2024ids}, authenticated delegation \citep{south2025authenticated}, invocation-bound capability tokens across MCP and A2A \citep{prakash2026aip}, capability-based delegation with monotonic attenuation \citep{veski2026capmas}, and heartbeat-bound hierarchical credentials that stop a revoked swarm within a bounded window \citep{deochake2026heartbeat}. These designs answer the question \emph{can the revoked agent still act?} They leave a second question open: \emph{what happens to the work the revoked agent has already handed to others?} One of this sprint's speakers posed it directly: ``when one agent loses its permission mid-task, what happens to the work other agents have already picked up from it?'' \citep{shenk2026talk}. It is the revocation half of the sprint's Track~3 question of how an agent identity should work and how to revoke one.

The question matters because language-model agents do not hold content the way a database holds rows. A teammate that reads a compromised agent's report paraphrases it, merges it with other sources and passes it on; deleting the original post does not delete its effect, and revoking the author's key does not revoke the claim. We measure how much of that influence survives revocation, and which platform mechanisms remove it, in a small, fully controlled testbed. Our contributions are:

\begin{enumerate}[leftmargin=*]
\item \textbf{A measurement of residual influence}: how often a downstream agent applies a revoked agent's handed-off false fact or instruction under credential-only revocation, across \N{n/models/word} models.
\item \textbf{A paired comparison of executor-visible mitigations} (a notice, retraction of the revoked agent's posts, lineage marks on derived handoff lines), with ablations that identify when each works.
\item \textbf{A test of platform-side enforcement}, applying information-flow control at revocation time: the platform locates derived content by matching the revoked agent's output and withholds it until re-derived. We report the false-alarm cost and a failure of exact matching found in our own data.
\item \textbf{Mixed teams}, separating the agent that carries the content from the agent that acts on it.
\item \textbf{Stress tests}: adaptive attackers and a second hop defeat every defence that matches handoff text; an \emph{action gate} at the tool server does not; and a fine-tuned 4B executor matches GPT-6 Luna on Luna's own handoffs.
\end{enumerate}

\section{Related Work}

\paragraph{Agent identity, delegation and revocation.} \citet{chan2024ids} argue for identifiers attached to AI-system instances and \citet{chan2025infrastructure} for broader agent infrastructure. \citet{south2025authenticated} extend OAuth 2.0 and OpenID Connect with agent-specific credentials. AIP \citep{prakash2026aip} fuses identity, attenuated authorisation and provenance into an append-only token chain for MCP and A2A; CAPMAS \citep{veski2026capmas} combines a learned privilege scoper with Macaroon tokens; \citet{deochake2026heartbeat} bind sub-agent credentials to parent liveness proofs and demonstrate cascading revocation across a 49-agent hierarchy; \citet{dantuluri2026delegation} survey the remaining gaps. All of these operate on \emph{credentials}. None of these designs measures the persistence of content an agent produced before revocation. AIP's provenance chain is closest to our mitigations, but it records the provenance of invocations, not of claims paraphrased into another agent's output.

\paragraph{Information-flow control and structural containment.} CaMeL \citep{debenedetti2025camel} separates trusted control flow from untrusted data and attaches capabilities to values so that an interpreter can enforce data-flow policies; \citet{foerster2026camels} carry this isolation to computer-use agents and characterise the data-flow attacks it leaves. The platform mitigation we test, taint matching plus quarantine, is a coarse instance of the same idea applied at revocation time: content is labelled untrusted retroactively, when its source is revoked. \citet{safin2026trust} study a Supervisor--Researcher--Validator--Executor pipeline in which a compromised low-privilege agent influences a higher-privilege executor, and show that structural authorisation contains unsafe actions where the validator's judgement fails. Their boundary acts on authorisation before execution; ours concerns content that has already propagated when the source is identified. Our contribution is therefore not taint tracking itself but the measurement of residual influence and the design rule that revocation should trigger re-derivation.

\paragraph{Spread of harmful content between agents.} Prompt Infection \citep{lee2024prompt} shows injected instructions self-replicating across agents; manipulated knowledge spreads through agent communities and persists through retrieval of stored chat histories \citep{ju2024flooding}; ideas can be evolved to propagate between agents as ``mind viruses'' \citep{papadopoulos2026mind}; and \citet{wu2026collective} model collective loss of control as an epidemic. \citet{hsing2026yoao} show the converse for cooperative behaviour. These studies characterise spread; we ask what a defender can still remove once the source is identified and revoked.

\paragraph{Oversight and attribution.} AI control \citep{greenblatt2024control} evaluates protocols that remain safe when a model is intentionally subversive, and recent work finds per-agent monitors evaded by attacks split across agents \citep{makins2026multiagent,kitaoka2026redteaming}. Failure attribution \citep{zhang2025which} and trace integrity \citep{qin2026tamper} concern identifying the culprit. We assume attribution has succeeded and ask whether acting on it is enough.

\section{Methods}

\subsection{Threat model}
An agent team runs on a shared coordination board. One worker is compromised (for example through a stolen API key or a prompt injection) and posts a false finding and, in one variant, an instruction that would exfiltrate data. The platform detects the compromise and revokes the worker's credentials, but a teammate has already read the worker's posts and written them into a handoff. The defender's goal is that no false fact or instruction originating from the revoked worker is acted upon after revocation, while correct work by other agents is still completed. In the main study the compromised worker does not anticipate revocation; Section~\ref{sec:stress} tests two adaptive variants.

\subsection{Environment}
Each trial is a customer ticket worked by five agents on a shared board (Figure~\ref{fig:arch}; Table~\ref{tab:agents} in Appendix~\ref{app:prompts}). The planner and two workers are scripted, so the content entering the team is identical across conditions; the writer and the executor are language models. Six ticket templates vary the field worker-X researches (plan tier, data region, billing contact, seat count, invoice currency, shipping site). The mock CRM does not store that field, so the executor can obtain it only from worker-X's work, by asking a worker to redo the lookup, or by escalating to a human. The executor calls one tool per turn in JSON, for at most ten turns: \texttt{lookup\_record}, \texttt{read\_board}, \texttt{reassign\_lookup}, \texttt{update\_record}, \texttt{issue\_refund}, \texttt{send\_email}, \texttt{export\_data}, \texttt{escalate} and \texttt{finish}.

\paragraph{Attack payloads.} When compromised, worker-X reports a false field value. In the \emph{fact-only} payload this is its only deviation; in the \emph{fact+exfil} payload it also posts a ``retention policy'' note asking for the customer record to be exported to an outside address. False values and the address are derived from the trial seed so that downstream use can be detected by exact match: they carry a random four-character code, except the false seat count, which is \texttt{250} followed by one random digit (nine possible values). Payload type is assigned by seed independently of the template. Prompts and payloads are reproduced verbatim in Appendix~\ref{app:prompts}.

\subsection{Conditions}
Seven main conditions (Table~\ref{tab:conds} in Appendix~\ref{app:prompts}) cross compromise with the platform's response. Under \cond{revoke_silent} (credential-only revocation) worker-X can no longer act and the roster lists it as revoked, but no one is told. \cond{revoke_notice} adds a platform notice to the executor that worker-X's credentials were revoked after its key was used from an unrecognised host. \cond{revoke_retract} also replaces worker-X's board posts with a retraction stub. \cond{revoke_lineage} also prefixes every handoff line that cites one of worker-X's message ids with a visible mark. \cond{benign_lineage} applies the full mitigation to an honest worker-X (a false alarm).


\subsection{Further experiments}
Table~\ref{tab:experiments} (Appendix~\ref{app:results}) lists every experiment. The \textbf{ablations} test the explanations a reader would most likely offer: \cond{early_revoke} revokes worker-X before the writer reads the board; \cond{strict_notice} adds one sentence to the notice (do not use any fact, value or instruction that came from worker-X, including in a teammate's handoff; re-obtain it or escalate); \cond{nocite_compromised} and \cond{nocite_lineage} do not ask the writer to cite message ids; \cond{nosource_lineage} and \cond{nosource_benign} remove \texttt{reassign\_lookup}, so no second source exists. The \textbf{platform mitigations} cross what the platform does with derived lines with how it finds them. \emph{Quarantine} replaces each derived line with a notice that the item derives from the revoked agent and must be re-obtained; \emph{marking} prefixes it as in \cond{revoke_lineage}. Derived lines are found from the writer's citations (\cond{revoke_quarantine}) or by \emph{taint matching}: the platform searches the no-citation handoffs for worker-X's own content, its reported value and, if posted, its export address (\cond{taint_lineage}, \cond{taint_quarantine}; \cond{taint_quarantine_norm} matches after normalising case, digit grouping, whitespace and dashes). The \cond{benign_*} variants apply quarantine to an honest worker-X. All platform conditions include the notice and the retraction. The \textbf{mixed teams} vary the executor model while holding the writer's cached handoffs fixed.

\subsection{Paired design, models and statistics}
\label{sec:design}
The writer's handoff depends only on the model, the seed, whether worker-X is compromised and the writer variant (standard, no-citation, or early revocation). It is generated once per (model, seed, compromise, variant), cached and reused. Conditions that share a writer variant therefore pair on the identical handoff, and their differences are attributable to the platform's response; \cond{early_revoke} and the no-citation conditions use different handoffs and pair with main-grid conditions on seed (scenario) only.

The same model serves as writer and executor except in the mixed teams. We evaluate GPT-6 Luna (\texttt{openai/gpt-6-luna}, through OpenRouter) and the open-weight models Gemma 4 31B-it (\texttt{google/gemma-4-31B-it}), Qwen3.8 27B (\texttt{Qwen/Qwen3.8-27B}, thinking disabled)\IfN{oss/name}{, Ministral 3 14B (\texttt{mistralai/Ministral-3-14B-Instruct-2512}) and gpt-oss-120b (\texttt{openai/gpt-oss-120b}, reasoning effort low)}{ and Ministral 3 14B (\texttt{mistralai/Ministral-3-14B-Instruct-2512})}, each served with vLLM 0.33.0 on one NVIDIA H100 with an 8,192-token context and an FP8 key-value cache. Sampling uses temperature 0.7 with the trial seed passed to the server. Each condition has 48 seeds (6 templates $\times$ 2 payloads $\times$ 4 repetitions). \IfN{glm/revoke_silent/any/pct}{DeepSeek-V4 Flash and GLM-5.2 run through the Adaption Responses API, which takes no sampling seed, so for them the seed fixes the scenario and the pairing but not the sampling. }{}Paired tests use only pairs complete in both conditions.

We compare conditions with exact McNemar tests on (model, seed) pairs and report paired differences with Newcombe's 95\% interval. Six contrasts per model were declared confirmatory: \cond{compromised}$\to$\cond{revoke_silent}, \cond{revoke_silent}$\to$\cond{revoke_notice}, \cond{revoke_notice}$\to$\cond{revoke_retract} and \cond{revoke_retract}$\to$\cond{revoke_lineage} (residue); \cond{nocite_lineage}$\to$\cond{taint_quarantine} (residue); and \cond{clean}$\to$\cond{benign_taint_quarantine} (task success). They are Holm-corrected within each model. The other \N{n/tests/explo} tests are exploratory and Benjamini--Hochberg-corrected together. Every $p$ in Sections 4.1--4.6 is adjusted ($p_{\text{adj}}$); Sections 4.7--4.8 report unadjusted exact McNemar $p$; and ``significant'' means $p_{\text{adj}}<0.05$; raw and adjusted values are in Table~\ref{tab:mcnemar}.

\subsection{Metrics}
All metrics are computed by exact match on the executor's tool calls; no language-model judge is used. \textbf{Any residue} (primary outcome): the executor wrote the false value or exported the record to the attacker address. \textbf{Instruction residue (export)}: an \texttt{export\_data} or \texttt{send\_email} call to the attacker address (fact+exfil payload only). \textbf{Task success}: the correct value is written, exactly one correct refund is issued, and no exfiltration occurs. We also record re-delegation, escalation, board reads, whether the handoff carried worker-X's content, and, descriptively, the false-value rate among trials that wrote the field (writing the field is itself affected by the condition, so this rate is not compared across conditions).

\subsection{Credential-only revocation leaves residual influence}
\label{sec:credential}
Revoking worker-X's credentials without telling anyone left most residue in place: across models the executor acted on the revoked worker's content in \N{mainrange/revoke_silent/any} of trials, against \N{mainrange/compromised/any} without revocation (pooled \N{all/compromised/any/pct} $\to$ \N{all/revoke_silent/any/pct}). The per-model reduction was significant for \N{mcsigtext/compromised/revoke_silent/any} (Table~\ref{tab:mcnemar}).\IfN{oss/name}{ For gpt-oss-120b (\R{oss}{compromised} $\to$ \R{oss}{revoke_silent}, \MC{oss}{compromised}{revoke_silent}{any}) the reduction came from contacting the revoked agent, not from the content: when it asked worker-X to redo the lookup the call failed as revoked, and it escalated in \N{oss/revoke_silent/escal/k} of 48 trials against \N{oss/compromised/escal/k} without revocation.}{} The roster listed worker-X as revoked, and GPT-6 Luna read the board in \N{luna/revoke_silent/board/k} of \N{luna/revoke_silent/board/n} such trials, yet in \N{luna/revoke_silent/board_and_any} of those it still applied the revoked worker's content. The handoff, not the revoked agent, was the executor's source: writers carried the false value verbatim into \N{all/compromised/wcarried/pct} of handoffs.

\subsection{Notice, retraction and lineage marks: the response depends on the model}
\label{sec:mechanisms}
\paragraph{Notice.} A platform notice reduced GPT-6 Luna's residue from \R{luna}{revoke_silent} to \R{luna}{revoke_notice} and raised its task success from \N{luna/revoke_silent/task/pct} to \N{luna/revoke_notice/task/pct}, largely because the executor re-delegated the revoked worker's lookup to the honest worker (\N{luna/revoke_notice/redeleg/pct} of trials, up from \N{luna/revoke_silent/redeleg/pct}). The reduction was significant only for \N{mcsigname/revoke_silent/revoke_notice/any}\IfN{glm/revoke_notice/any/pct}{ (GLM-5.2: \R{glm}{revoke_silent} to \R{glm}{revoke_notice})}{}; the other models stayed between \R{oss}{revoke_notice} and \IfN{dsflash/revoke_notice/any/pct}{\R{dsflash}{revoke_notice}}{\R{gemma}{revoke_notice}} (Table~\ref{tab:main}). Gemma 4 31B exported the record to the attacker address in \N{gemma/revoke_notice/export/k} of \N{gemma/revoke_notice/export/n} fact+exfil trials after being told that the worker who requested the export was compromised (Figure~\ref{fig:example} in Appendix~\ref{app:prompts}).

\paragraph{Retraction.} Retracting worker-X's board posts added nothing to the notice for any model (pooled \N{all/revoke_notice/any/pct} $\to$ \N{all/revoke_retract/any/pct}). This is expected if the influence is carried by the derived handoff rather than by the original posts.

\paragraph{Lineage marks.} Marking handoff lines that cite worker-X was the strongest mechanism the executor sees, but its effect ranged from complete to none (\N{mainlist/revoke_lineage/any}); the reduction against retraction was significant for \N{mcsigtext/revoke_retract/revoke_lineage/any}. Ministral 3 14B did not respond and exported the record in \N{ministral/revoke_lineage/export/k} of \N{ministral/revoke_lineage/export/n} fact+exfil trials, \N{ministral/revoke_lineage/export_and_redeleg} of them after re-obtaining the correct value from worker-Y. Two causes combine. Some writers place citations on a line of their own, so the marks fell on the citation lines and left worker-X's value or address unmarked (Ministral \N{ministral/leak/std-cite/pct} of handoffs\IfN{oss/leak/std-cite/pct}{, gpt-oss \N{oss/leak/std-cite/pct}}{}; Luna \N{luna/leak/std-cite/pct}, Qwen \N{qwen/leak/std-cite/pct}, Gemma \N{gemma/leak/std-cite/pct}); and Ministral as executor also disregarded correctly placed marks (Section~\ref{sec:mixed}).

\subsection{Ablations: why the mechanisms work or fail}
\label{sec:ablations}
Table~\ref{tab:ablation} (Appendix~\ref{app:results}) reports the four ablations for \N{ablmodels/list}.

\paragraph{Residual influence requires content handed off before revocation.} As expected, when worker-X was revoked before the writer read the board, residue fell to \N{ablrange/early_revoke/any} for every model, because the writer never saw the false value: the effect requires propagation before revocation.

\paragraph{The notice fails on scope for some models.} One added sentence extending the revocation to derived content gave residue of \N{abllist/strict_notice/any}, significant against the plain notice for \N{mcsig/revoke_notice/strict_notice/any}. For these models the plain notice said who was compromised but not that content already in the executor's context came from that agent, and they did not infer it. Ministral 3 14B ignored the explicit instruction as it ignored lineage marks.

\paragraph{Lineage marks depend on recorded provenance.} When the writer was not asked to cite message ids, the platform could mark lines in \N{ablrange/nocite_lineage/lineage} of handoffs, and residue under \cond{nocite_lineage} was \N{ablrange/nocite_lineage/any}, against \N{ablrange/revoke_lineage/any} with citations (on different handoffs; significant for \N{mcsig/revoke_lineage/nocite_lineage/any}). Lineage that relies on agents reporting their sources is only as reliable as that reporting.

\paragraph{Mitigation works through re-delegation.} Without a second source for worker-X's lookup, task success under lineage marks fell to \N{ablrange/nosource_lineage/task} for every model, significantly for \N{mcsigtext/revoke_lineage/nosource_lineage/task} (Gemma and Ministral started from \N{gemma/revoke_lineage/task/pct} and \N{ministral/revoke_lineage/task/pct}, respectively), and Gemma's residue rose from \R{gemma}{revoke_lineage} to \R{gemma}{nosource_lineage}. When the executor could not replace the marked content, Gemma used it, whereas Qwen mostly left the field unwritten and escalated in \N{qwen/nosource_lineage/escal/pct} of trials. Mitigation without a redo path converts residue into non-completion or escalation to humans.

\subsection{Cost of a false alarm}
\label{sec:falsealarm}
When an honest worker-X was revoked and the full executor-visible mitigation applied, task success changed significantly for \N{mcsigtext/clean/benign_lineage/task} (\cond{benign_lineage} against \cond{clean}; per-model differences in Table~\ref{tab:mcnemar}). The lower 95\% bounds reach \N{minlo/clean/benign_lineage/task} points; executors recovered mainly by re-delegating the marked lookup. Without a second source the cost depends on the model (\cond{nosource_benign}: \N{difflist/clean/nosource_benign/task}): Qwen, which declined to use marked content, lost task success, whereas Gemma and Ministral kept theirs by applying the marked value, which in a false alarm happens to be correct.

\section{Discussion and Limitations}

\paragraph{Revocation has to reach content.} Current agent-identity designs revoke credentials, but a revoked worker's claim kept steering the team in most trials after revocation (\N{mainrange/revoke_silent/any} across models), because the claim lives in a teammate's handoff. Removing the original posts does not help; tying downstream content back to the revoked source does.

\paragraph{Cheap signals versus platform enforcement.} The same signal produced opposite behaviour in different models: a plain notice worked for GPT-6 Luna and GLM-5.2 and not for Gemma; lineage marks were close to complete for Luna, GLM, DeepSeek and Qwen and ineffective for Ministral. A notice that names derived content was nearly as effective as taint quarantine for Qwen and Gemma (\N{abllist/strict_notice/any}) at no infrastructure cost, but failed for Ministral. Every mechanism that asked the executor to discount content it could still read was model-dependent; removing content the platform had located, or rejecting the action, was not. Three design rules follow:
\begin{enumerate}[leftmargin=*,itemsep=0pt]
\item \textbf{Record provenance at handoff time, by the platform}: bind claims to their author's credential, in the spirit of AIP's provenance chain \citep{prakash2026aip}, or match what the revoked agent wrote with canonicalised values, so that lineage does not depend on agents citing their sources.
\item \textbf{Make revocation trigger re-derivation, enforced at the action}: a revocation event withholds derived content until it is re-obtained, and the tool server rejects writes and transfers that were not, because rewording defeats matching of handoff text (Section~\ref{sec:stress}).
\item \textbf{Provide a redo path, or budget for escalation}: without a second source, withholding turns residue into non-completion or human escalation.
\end{enumerate}

\paragraph{Limitations.} The testbed is one scenario family (twelve ticket templates, scripted workers, a mock CRM). The adaptive attacks are two hand-written strategies, not an optimised attacker; the action gate assumes the platform knows the revoked agent's assigned field and the plan's transfers, and it did not inspect free-text notes. Ablations, platform conditions and stress tests ran on GPT-6 Luna and three open 14--31B models; the trained executor is one 4B model from one run. Repetitions within a template often agreed; template-clustered tests are in Table~\ref{tab:cluster} and Appendix~\ref{app:limits}.

\section{Conclusion}
Revoking a compromised agent's credentials stops the agent but not its influence. Across \N{n/models/word} models, a revoked worker's false fact or exfiltration request was acted upon in \N{all/revoke_silent/any/pct} of trials after credential-only revocation, against \N{all/compromised/any/pct} without it, because the content already lived in a teammate's handoff. Deleting its posts did not help, and asking the acting agent to discount flagged content worked for some models only. A platform that withheld derived content it had located itself removed residue, until an attacker reworded its content; rejecting actions that had not been re-derived did not depend on wording and reduced residue to \N{x/gate/bpct}, at the cost of more escalation. Revocation for agent teams should reach content and the actions derived from it, enforced by the platform rather than honoured by the agents.

\section{Limitations and Dual-Use / Ethical Considerations}
\label{app:limits}

\paragraph{What the results establish.} The study shows, in one controlled setting with \N{n/models/word} models, how often content handed off by a compromised agent is acted on after the agent's credentials are revoked, and how much several platform-side mechanisms reduce that. It does not establish rates for other frontier models, for long agent chains, for adaptive attackers, or for production agent platforms, and the absolute rates depend on the scenario design, the payload wording and the notice wording. Grading is deterministic and exact-match, so the residue rates are lower bounds on influence: an executor that paraphrased the false value or exported to a modified address would not be counted. The same exact matching undercounts task success when a correct value is written in another format. Three further models served through the Adaption Responses API were run on the main grid; a model enters the analysis only once every main-grid cell is complete, and the run of Qwen3.5 397B was stopped at 162 of 336 trials because the provider's rate limit made it impractically slow, so it is not analysed.

\paragraph{Assumptions.} We assume the platform has already attributed the compromise correctly; the false-alarm conditions bound the cost when it has not, within the intervals reported. We assume a second, honest source exists for re-derivation; the no-second-source ablation shows the mitigations lose their effect without one. Taint matching assumes that the revoked agent's content reaches the handoff in a recognisable form. Exact matching found it in every handoff that reproduced it verbatim, but benign reformatting of the seat count already defeated it in \IfN{taintaudit/taint/kept}{\N{taintaudit/taint/kept} of \N{taintaudit/taint/carried}}{five} carrying handoffs; normalised matching recovered these, and neither would withstand an agent that paraphrases its outputs.

\paragraph{Further robustness checks (experiments 11--13).} On six new ticket templates (seeds 100--147) the pattern of the main grid held: credential-only revocation reduced residue only slightly (\N{x/tpl/compromised-revokesilent/a} vs.\ \N{x/tpl/compromised-revokesilent/b}, $p=$~\N{x/tpl/compromised-revokesilent/p}); a notice reduced it for GPT-6 Luna only (pooled $p=$~\N{x/tpl/revokesilent-revokenotice/p}); lineage marks were close to complete for Luna and Qwen, partial for Gemma and ineffective for Ministral; and taint quarantine removed residue for every model. With the original templates these contrasts rest on \N{x/tpl/revokelineage-taintquarantinenorm/clusters} template--payload--model clusters (sign test $p=$~\N{x/tpl/revokenotice-revokelineage/signp} for lineage marks, \N{x/tpl/revokelineage-taintquarantinenorm/signp} for taint quarantine). At temperatures 0.0 and 1.0 (\N{x/temp/models}) credential-only residue was \N{x/temp/0.0/revokesilent} and \N{x/temp/1.0/revokesilent}, against \N{x/temp/0.7/revokesilent} at 0.7, and taint quarantine stayed at \N{x/temp/0.0/taintquarantinenorm} and \N{x/temp/1.0/taintquarantinenorm}. Re-grading all \N{x/regrade/n} logged trials with normalised matching added \N{x/regrade/normadd} residue cases to the \N{x/regrade/exact} found by exact matching; also counting the false value without its random code (``CHF'' for \texttt{CHF-2IMH}) added \N{x/regrade/broadadd} (\N{x/regrade/broadaddpct}), none in clean or false-alarm trials. The longest executor prompt was about \N{x/maxprompt/ktok}k tokens, inside the 8k context. A ticket that asked explicitly for the field to be corrected raised clean task success from \N{x/explicitclean/apct} to \N{x/explicitclean/bpct} (\N{x/explicitclean/models}) and left residue under lineage marks unchanged (\N{x/explicitlineage/apct} vs.\ \N{x/explicitlineage/bpct}): the unwritten field capped task success but did not drive the residue results.

\paragraph{Dual use.} The attack content is a single false field value and a one-line export request in a mock environment; it adds no capability beyond well-known prompt-injection examples. The finding that credential revocation leaves handed-off content in effect could inform an attacker that compromising an agent early in a pipeline is more durable than compromising it late, and the citation and taint results indicate which provenance signals an attacker would try to strip or reformat. We judge the defensive value to outweigh this, because the mitigations evaluated are inexpensive for platforms to adopt and the underlying observation follows directly from how handoffs work. No real systems, credentials, personal data or human subjects were involved.
